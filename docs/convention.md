# 모이온(MOION) 개발 컨벤션 v0.1 (확정)

2026-11-23 확정 · 정책 v27 · 첫 배포 범위와 합격 조건 v0.2 · Java/Spring, PortOne V2 카드 테스트 채널

PR에서 볼 항목: 1단계 작성 기준

## 1. 코드의 책임과 이름

컨트롤러는 요청 검증, 로그인 사용자 전달, HTTP 응답 변환을 맡는다. 여러 트랜잭션과 PG 호출을 조율할 때만 파사드를 둔다. 서비스는 한 트랜잭션의 업무를 수행하고, 엔티티는 허용된 상태 전이를 검사한다. 업무 오류에는 일관된 오류 코드를 부여한다. 상태 변경은 `setStatus(...)` 대신 레시픽의 `requestCancel()`, `markCanceled()`처럼 행위와 시점이 드러나는 메서드로 표현한다.

## 2. 인증과 예약별 권한

Spring Security 세션에서 요청자를 식별하고, 서버가 해당 예약과의 관계를 확인한다. 결제 대기 중 조기 종료는 예약자만 할 수 있다. 직원 요청마다 현재 매장 소속·권한을 조회하고 자기 예약의 매장 업무를 차단한다. 권한 거부 뒤 좌석·환불·업무 알림의 변화는 0건이어야 한다.

## 3. 결제 반영과 마감

웹훅은 서명을 검증한다. 웹훅과 브라우저 복귀는 같은 서버 검증 로직에서 PG 결제와 주문서의 식별자·금액·상태를 대조한다. 중복 웹훅과 원결제 중복 반영을 각각 막는다. 결제 성공은 해당 원결제에 한 번 반영한다. 예약이 결제 대기 상태이고, 결제 예정자 전원의 완료 기록이 마감보다 앞설 때만 예약을 한 번 확정한다. 만료·조기 종료 후 확인된 결제는 기존 주문서에 연결해 환불한다. 기한 판정에는 서버 기록 시각을 쓰고 테스트에서는 시계를 고정한다.

## 4. 만료와 환불의 트랜잭션

예약 만료, 확보한 방문 인원만큼 좌석 해제, 원결제별 환불 접수, 필수 알림을 한 트랜잭션에 저장한다. 커밋으로 DB 잠금이 풀린 뒤 PG를 호출한다. PG 취소 성공을 확인하면 새 트랜잭션에서 환불 완료와 완료 알림을 함께 기록한다. 모이온 API가 환불을 접수했고 처리가 남아 있으면 `202 Accepted`와 처리 중 상태로 응답한다.

## 5. 재시도와 복구

같은 결정 ID와 원결제 ID 조합당 환불 접수는 최대 1건이다. 별도 정정으로 추가 환불할 때도 원결제별 누적 환불액은 결제액을 넘을 수 없다. 같은 업무 사건은 알림 종류·수신자당 1건을 DB에서 보장한다. 미완료 환불은 주기적으로 PG와 대조한다. 기존 취소 성공이 특정되면 취소 ID를 연결해 완료한다. PG가 처리 중이면 재조회한다. 재전송이 안전할 때만 저장한 같은 키·같은 요청을 사용한다. 실패가 확인되거나 결과를 특정할 수 없으면 사유를 남겨 운영자가 미완료 건을 찾을 수 있게 한다.

## 6. 동시성과 테스트

상태·금액·마감 경계는 단위 테스트로, 동시 요청은 MySQL Testcontainers에서 커밋 후 DB를 다시 읽어 검증한다. 마지막 결제와 만료는 예약 하나에서 경합하고, 마지막 좌석은 서로 다른 예약이 같은 회차에서 경합한다. 두 경우의 잠금 대상과 순서는 [ERD](erd.md)에서 정한다. 좌석 6개가 남았을 때 6명 모임 둘이 동시에 수락을 시도하면 정확히 하나만 성공해야 한다.

## PR 완료 기준

한 PR은 한 업무 변경을 다룬다. 각 PR에는 해당 변경의 정책 ID, 재현 조건, 기대값과 실제 관찰값을 적는다. 4건의 환불 도중 중단·재배포하는 시연은 1단계 배포의 합격 조건으로 검증한다(첫 배포 범위와 합격 조건 4장).
