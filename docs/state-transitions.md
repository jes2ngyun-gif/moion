# 모이온(MOION) 도메인별 상태 전이표

기준: [비즈니스 정책](policy.md) POL-001~POL-017. 문서 상태: 확정. 구현 상태: 구현 전.

- 상태 이름은 확정된 정책 기준이며, 상세 상태는 설계 단계에서 확정한다. 1단계 테이블과 상태 값은 [ERD](erd.md)와 [API 명세](api.md)를 따른다.
- 매장 응답 대기와 결제 대기에서는 각각 한 번만 전이한다.
- 방문 확인은 예약 상태를 바꾸지 않고 별도 기록으로 남긴다([[POL-008] 방문 확인과 매장 지급 대상 확정](policy.md#pol-008)).

## 예약

| 매장 응답 대기 | 매장 수락 | 결제 대기 | 응답 기록 시각 < 응답 기한, 회차 최대 방문 인원 이내(동반인 포함), 결제 마감 = 수락 시각 + 30분, 좌석 확보·인원 잠금 |

| 매장 응답 대기 | 응답 기한 도달 | 메뉴 편집 | 요청 만료, 결제 없음, 주문서 보존 |

| 결제 대기 | 권한 있는 매장 직원의 사유 기록 취소 | 매장 사정 취소 | 좌석 해제·위약금 0원·전액 환불 ([[POL-015] 매장 사정 취소](policy.md#pol-015)) |

| 확정 | 방문 확인 | 확정 (변동 없음) | 방문 확인 기록과 지급 대상 확정만 남김. 같은 예약에서 예약 전체 취소와 하나만 성립 |
| 확정 | 회차 종료 시각까지 방문 미확인 | 확정 (유지) | 방문 결과 확인 목록에 올리고 지급·환불 보류, 매장 응답 또는 24시간 후 처리 ([[POL-010] 회차 종료 후 방문 미확인 예약의 처리](policy.md#pol-010)) |
| 확정(방문 미확인) | 전원 노쇼 신고 후 72시간 이의 없음, 또는 운영자 매장 응답 유지 + 이의 기간 종료 | 확정 (유지) | 결제 전 노쇼 위약금 확인 기록이 있으면 결제 건별 20%(원 미만 버림)를 위약금 지급 대상으로, 나머지 환불 접수. 약정 없는 예약이면 전액 환불 ([[POL-012] 일행 전원 노쇼 확정 시 위약금](policy.md#pol-012)) |
| 확정 | 권한 있는 매장 직원의 사유 기록 취소 | 매장 사정 취소 | 방문 기록·제공·수납이 모두 없을 때만 직원이 직접 확정: 좌석 해제·위약금 0원·전액 환불. 하나라도 있으면 직원은 근거를 제출하고 운영자가 대조해 전액 환불 또는 금액 정정으로 확정 ([[POL-015] 매장 사정 취소](policy.md#pol-015), [[POL-016] 역할과 예약별 권한](policy.md#pol-016)) |
| 확정(현장 접수) | 현장 접수 뒤 예약자 취소 | 취소 보류 접수 | 요청 시각 보존·환불 보류, 회차 후 제공 여부로 [[POL-009] 예약 확정 이후 예약자 취소의 환불 기준](policy.md#pol-009) / [[POL-015] 매장 사정 취소](policy.md#pol-015) / 이용 처리 / 정정 중 하나만 적용 ([[POL-013] 코드 없는 현장 접수](policy.md#pol-013)) |

상태는 바로 바뀌고, 환불은 결제 건별로 완료될 때까지 따로 추적한다. 종료된 모임은 다시 열리지 않는다.

## 확정 주문서(order_sheet)

설계 기준이며 테스트 결과가 아니다. 상태 값은 [ERD](erd.md)의 `order_sheet.status`(유효/무효)다.

- 기준: 이 주문서로 예약 확정에 이르렀는가.
- 예약 확정 전에 요청이나 결제 대기가 끝나면, 그 시점에 해당 주문서를 무효로 바꾼다. 새 버전이 생길 때까지 기다리지 않는다.
- 예약이 한 번 확정됐다면 이후 전체 취소·매장 사정 취소·정정이 있어도 당시 주문서는 유효로 보존한다.
- 아래 표에서 "업무 결과"는 기존 확정 정책에 명시된 내용이고, "주문서 상태"는 그 결과를 `order_sheet.status`에 표시하는 방식으로 2026-11-23에 정했다.

| 현재 상태 | 사건 | 업무 결과 (확정 정책) | 주문서 상태 (2026-11-23 결정) |
|---|---|---|---|
| 없음 | 수락 요청이 성립해 메뉴·금액이 확정됨 | 주문서와 매장 수락 요청을 한 번에 저장. 미확인자가 있거나 최종 청구액 검사에서 거부되면 주문서 0건. 같은 요청의 재시도는 기존 주문서를 반환 ([[POL-001] 참여자별 결제 금액 산정 방식](policy.md#pol-001), [[POL-006] 참여 확정의 정의](policy.md#pol-006), [매장 수락 요청](api/store-request.md#api-4-1)) | 유효 생성 |
| 유효 | 매장 거절 · 요청 철회 · 60분 응답 기한 만료 | 결제 없음, 모임은 메뉴 편집으로 돌아감. 다시 요청하면 새 주문서 버전을 만듦 ([[POL-002] 매장 수락 절차와 결제 제한 시간](policy.md#pol-002)) | 무효. 요청이 끝난 시점에 처리 |
| 유효 | 매장 응답 대기 중 예약자 이탈 | 기존 수락 요청 취소, 결제 없음, 모임 종료 ([[POL-007] 예약자의 역할](policy.md#pol-007)) | 무효 |
| 유효 | 매장 수락 | 예약 생성, 결제 대기 시작. 수락 전에는 결제를 시작할 수 없음 ([[POL-002] 매장 수락 절차와 결제 제한 시간](policy.md#pol-002)) | 유효 유지 |
| 유효 | 결제 대기 중 예약자 조기 종료 | 즉시 좌석 해제, 메뉴 편집 복귀, 결제 건별 전액 환불 ([[POL-002] 매장 수락 절차와 결제 제한 시간](policy.md#pol-002)) | 무효 |
| 유효 | 결제 대기 중 30분 결제 기한 만료 | 예약 만료, 즉시 좌석 해제, 모임 종료, 결제 건별 전액 환불 ([[POL-002] 매장 수락 절차와 결제 제한 시간](policy.md#pol-002)) | 무효 |
| 유효 | 결제 대기 중 예약자 이탈 확정 | 마지막 결제와 이탈 중 어느 결과가 먼저 성립했는지 판정한 뒤, 이탈이 성립하면 좌석 해제·모임 종료·결제 건별 전액 환불 ([[POL-007] 예약자의 역할](policy.md#pol-007)) | 무효 |
| 유효 | 결제 대기 중 매장 사정 취소 | 좌석 해제·위약금 0원·전액 환불 ([[POL-015] 매장 사정 취소](policy.md#pol-015)) | 무효 |
| 유효 | 결제자 전원 결제로 예약 확정 | 예약 확정 ([[POL-002] 매장 수락 절차와 결제 제한 시간](policy.md#pol-002)) | 유효 유지. 당시 품목·단가·결제자별 몫의 근거 |
| 유효 | 확정 후 예약 전체 취소 | 예약 취소, 결제 건별 환불 ([[POL-009] 예약 확정 이후 예약자 취소의 환불 기준](policy.md#pol-009)) | 유효 유지 |
| 유효 | 확정 후 매장 사정 취소 | 위약금 0원·전액 환불 또는 운영자 대조 후 정정 ([[POL-015] 매장 사정 취소](policy.md#pol-015)) | 유효 유지 |
| 유효 | 확정 후 금액 정정 | 원결제액 비례 정정, 차액 환불 ([[POL-011] 방문 결과에 대한 이의 신청과 운영자 처리](policy.md#pol-011)) | 유효 유지 |

예약자 이탈은 발생 시점에 따라 다르게 처리한다.

- 메뉴 편집 중: 이번 요청의 주문서가 없으므로 바꿀 주문서가 없다.
- 매장 응답 대기 중: 기존 요청을 취소하므로 그 주문서를 무효로 바꾼다.
- 결제 대기 중: 마지막 결제와 이탈 중 어느 결과가 성립했는지 먼저 판정한다.
- 예약 확정 후: [[POL-007] 예약자의 역할](policy.md#pol-007)에 따라 예약 전체 취소 절차로 넘어가며, 주문서는 유효로 보존한다.

- "유효"만으로 새 결제가 허용되지는 않는다. 예약의 결제 대기 상태와 결제 시작 기한을 함께 검사한다.
- "무효"인 주문서도 품목·단가·결제자별 몫을 보존한다. 늦게 도착한 승인은 원래 주문서와 원결제에 연결해 처리한다. 예를 들어 옛 주문서의 20,000원 승인은 그 주문서 기준으로 20,000원 환불하고, 새 주문서의 18,000원 결제에는 영향을 주지 않는다([검산 사례 9-6](verification-cases.md#9-재배포-복구)).

## 결제

| 현재 상태 | 이벤트 | 다음 상태 | 조건 |
|---|---|---|---|
| 결제 대기 | PG 결제 성공 확인 | 결제 완료 | 결제 시작 기록 시각 < 결제 마감 − 5분, 서버 저장 금액과 일치, 결제 완료 기록 시각 저장 |
| 결제 완료 | 예약 만료·조기 종료·모임 종료 | 환불 요청 | 결제 건별 전액, 환불 접수 알림. 환불 접수(서버 저장) 후 PG 취소 완료 확인 시 환불 완료 |
| 결제 완료 | 마감 또는 조기 종료 후 기록된 결제로 판정 | 환불 요청 | 결제 완료 기록 시각이 마감 시각 또는 조기 종료 기록 시각과 같거나 늦음, 예약 복구 없음, 전액 환불, 환불 접수 알림. 환불 접수(서버 저장) 후 PG 취소 완료 확인 시 환불 완료 |
| 결제 완료 | 예약 전체 취소 | 환불 요청 | 환불액 = 결제 금액 − 위약금(0% 또는 15%, 원 미만 버림), 환불 접수 알림. 환불 접수(서버 저장) 후 PG 취소 완료 확인 시 환불 완료 |
| 결제 완료 | 매장 사정 취소·노쇼 확정·운영자 결론(전액 환불·금액 정정) | 환불 요청 | 저장한 결제 건별 환불액으로 요청. 0원 건은 PG에 요청하지 않음 ([[POL-011] 방문 결과에 대한 이의 신청과 운영자 처리](policy.md#pol-011), [[POL-012] 일행 전원 노쇼 확정 시 위약금](policy.md#pol-012), [[POL-015] 매장 사정 취소](policy.md#pol-015)) |
| 결제 완료 | 회차 종료 시 방문 미확인으로 '방문 결과 확인 필요' 목록에 오른 예약 중, 24시간 동안 매장 응답과 결제자 이의가 모두 없음 | 환불 요청 | 결제 건별 전액 환불 접수, 사유 "매장 미응답", 방문 여부 "알 수 없음". 마감 전에 기록된 매장 응답이 있으면 제외. 환불 접수 기록을 저장해 재배포 뒤 남은 건만 이어서 처리 ([[POL-010] 회차 종료 후 방문 미확인 예약의 처리](policy.md#pol-010)) |
| 결제 완료(일부 환불 완료) | 운영자 정정 승인 | 환불 요청(추가) | 최종 앱 환불 목표액 − 완료된 앱 환불액만 추가 접수, 0원이면 PG 요청 생략, 같은 정정 ID 재시도는 한 번만 반영. 기존 환불이 진행 중이거나 결과 불명이면 정정 결정과 목표액을 먼저 저장하고, 기존 환불 결과를 확인한 뒤 차액을 계산 ([[POL-011] 방문 결과에 대한 이의 신청과 운영자 처리](policy.md#pol-011)) |
